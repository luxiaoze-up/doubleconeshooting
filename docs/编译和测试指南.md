# Ubuntu 24.04 编译和测试指南

本文是 DoubleConeShooting 的唯一受支持构建路径，目标平台为 Ubuntu 24.04 x86-64。

## 1. 系统依赖

安装基础工具和仓库可直接引用的开发包：

```bash
sudo apt update
sudo apt install -y \
  build-essential cmake pkg-config git \
  libomniorb4-dev libzmq3-dev qtbase5-dev \
  python3 python3-venv python3-pip
```

现场真实模式还需要：

- Tango Controls 开发库、数据库和 Starter；
- MariaDB；
- open62541（OPC UA 模式）；
- Snap7（S7 模式）；
- 厂商提供的 Ubuntu x86-64 硬件 SDK。

仓库内的 `lib/libLTSMC.so` 是运动控制器运行库。用下面的命令检查架构和缺失依赖：

```bash
file lib/libLTSMC.so
ldd lib/libLTSMC.so
```

## 2. Python 环境

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -U pip
python -m pip install -r requirements.txt
python -m pip install -r gui/requirements.txt
python -m pip install -r gui/vacuum_system_gui/requirements.txt
python -m pip install -r gui/six_dof_debug_gui/requirements.txt
```

不要把 `.venv/`、`__pycache__/`、覆盖率文件或测试报告提交到仓库。

## 3. C++ 配置与编译

Debug 构建：

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build --parallel
```

Release 构建：

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
```

如果切换了编译器、Tango 版本、Qt 版本或 SDK，重新生成 `build/`，不要复用旧机器的 `CMakeCache.txt`。

CMake 会按依赖探测结果构建设备服务和可选的 `main_controller`。Tango、omniORB 和 ZeroMQ 是设备服务主线依赖；open62541 与 Snap7 决定相应 PLC 协议是否启用。

## 4. 配置检查

```bash
export TANGO_HOST=127.0.0.1:10000
tango_admin --ping-database
python3 scripts/check_mode.py
python3 scripts/check_reflection_config.py
```

真实硬件联调前逐项核对：

- `config/devices_config.json` 中的控制器 IP、设备名、轴号和 IO；
- `config/vacuum_system_config.json` 中的 PLC 协议、地址和超时；
- 主机网卡是否处于 `192.168.1.0/24` 设备网段；
- 急停、限位、刹车、电源和机械行程是否安全；
- `TANGO_HOST` 是否指向预期数据库。

## 5. 自动化测试

不连接硬件的基础检查：

```bash
python3 -m compileall -q gui scripts tools
scripts/run_tests.sh --unit -v
```

生成报告：

```bash
scripts/run_tests.sh --html --cov
```

测试代码位于 `scripts/unit_test/`。部分历史用例虽然位于该目录，但仍会创建 Tango `DeviceProxy` 或发送运动命令；执行前必须阅读测试文件并确认它是否真正隔离硬件。

## 6. 真实设备联调

推荐顺序：

1. 检查 MariaDB、Tango Database 和 Starter；
2. 注册或更新 Tango 设备属性；
3. 启动运动控制、编码器及其他设备服务；
4. 确认通用启动器中的真空系统已经就绪；若不使用通用启动器，再单独启动真空系统；
5. 验证状态和只读属性；
6. 在低速、小行程、有人监护的条件下执行运动命令；
7. 最后启动 GUI 做端到端验证。

```bash
python3 scripts/register_devices.py --config config/devices_config.json --force
python3 scripts/start_servers.py
python3 gui/vacuum_chamber_gui/main.py
```

`scripts/start_servers.py` 已包含 `VacuumSystem`。只有在不运行通用启动器时，才使用 `scripts/start_vacuum_system.sh` 单独启动该服务。

## 7. 常见故障

### 找不到 Tango 头文件或库

确认 `tango.h` 和 `libtango.so` 位于 `/usr/include/tango`、`/usr/local/include/tango`、`/usr/lib` 或 `/usr/local/lib`，然后重新运行 CMake。

### 找不到 omniORB 或 ZeroMQ

```bash
sudo apt install libomniorb4-dev libzmq3-dev
```

### `libLTSMC.so` 加载失败

```bash
file lib/libLTSMC.so
ldd lib/libLTSMC.so
```

确认系统为 x86-64，动态链接器能找到所有依赖，并从项目根目录启动程序。

### GUI 无法启动

确认 Ubuntu 图形会话存在：

```bash
printf 'DISPLAY=%s WAYLAND_DISPLAY=%s\n' "${DISPLAY:-}" "${WAYLAND_DISPLAY:-}"
python3 -c 'from PyQt5.QtWidgets import QApplication; print("PyQt5 OK")'
```

无界面语法/启动检查可显式设置 `QT_QPA_PLATFORM=offscreen`，但不能替代现场 GUI 验收。

### Tango 调用超时

检查 `TANGO_HOST`、数据库状态、设备服务实例名、主机名解析和防火墙。必要时运行 `scripts/setup_omniORB.sh` 禁用 omniORB 反向 DNS 查询。
