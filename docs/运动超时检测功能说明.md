# 运动超时检测功能说明

## 问题描述

在某些情况下，底层SMC驱动函数 `smc_check_done()` 会一直返回0（表示运动中），但实际上电机已经停止或根本没有运动。这导致：

1. **运动控制器设备** 状态一直保持 `MOVING`
2. **大行程设备** 读取到运动控制器状态为 `MOVING`，自身也保持 `MOVING`
3. **用户界面** 显示设备卡在运动状态，无法执行后续操作

### 问题根源

根据日志分析（motioncontroller-3.log）：
- 12:41:49 发出运动命令 `smc_pmove_unit(axis=6, dist=14147)`
- 12:59:09 开始，`smc_check_done()` 持续返回 0（运动中）
- 持续时间超过17分钟，显然异常

可能原因：
- 电机未使能或驱动器故障
- 编码器未连接或配置错误（日志显示编码器位置始终为0）
- 运动控制器硬件状态寄存器未正确更新
- 限位触发但未被正确处理

## 解决方案

### 实现的超时检测机制

在运动控制器设备 (`motion_controller_device`) 中添加了基于**位置稳定性的超时检测**：

#### 1. 跟踪变量

```cpp
// 在 motion_controller_device.h 中添加：
std::map<short, std::chrono::steady_clock::time_point> axis_move_start_time_;      // 轴运动开始时间
std::map<short, double> axis_last_position_;                                       // 轴上次位置
std::map<short, std::chrono::steady_clock::time_point> axis_position_stable_time_; // 位置稳定开始时间
static constexpr double POSITION_STABLE_THRESHOLD = 0.1;  // 位置稳定阈值(0.1 unit)
static constexpr int POSITION_STABLE_TIMEOUT_MS = 2000;   // 位置稳定超时时间(2秒)
```

#### 2. 检测逻辑

在 `always_executed_hook()` 中，对每个运动中的轴：

1. **检查 `smc_check_done()` 返回值**
   - 如果返回1（已停止）：正常完成，清除跟踪数据
   - 如果返回0（运动中）：继续检查位置稳定性

2. **读取当前位置**
   ```cpp
   smc_get_position_unit(card_id_, axis, &current_pos);
   ```

3. **位置稳定性检测**
   - 计算位置变化量：`|current_pos - last_pos|`
   - 如果变化量 < 0.1 unit：认为位置稳定
   - 如果位置稳定时间 > 2秒：**强制认为运动完成**

4. **强制完成处理**
   ```cpp
   WARN_STREAM << "Axis " << axis << " position stable for " << stable_duration 
               << "ms, forcing motion complete despite smc_check_done=0";
   // 从 moving_axes_ 中移除该轴
   // 如果所有轴都停止，设备状态从 MOVING 转为 STANDBY
   ```

#### 3. 初始化

在运动命令（`moveRelative`, `moveAbsolute`, `moveZero`）发出时，清除该轴的旧跟踪数据：

```cpp
axis_move_start_time_.erase(axis);
axis_last_position_.erase(axis);
axis_position_stable_time_.erase(axis);
```

### 优势

1. **自动恢复**：无需手动干预，系统自动检测并恢复
2. **可配置参数**：
   - `POSITION_STABLE_THRESHOLD`：位置稳定阈值
   - `POSITION_STABLE_TIMEOUT_MS`：超时时间
3. **详细日志**：记录检测过程和决策依据
4. **不影响正常运动**：只在 `smc_check_done()` 异常时触发

### 局限性

- **依赖位置读取**：如果 `smc_get_position_unit()` 也失败，检测机制无效
- **不处理根本问题**：只是规避症状，硬件问题仍需排查
- **可能误判**：如果运动速度极慢，可能被误判为完成

## 调试建议

如果问题仍然出现：

1. **检查硬件连接**
   - 电机驱动器电源
   - 编码器连接线
   - 限位开关

2. **检查运动控制器配置**
   ```python
   import PyTango
   motion = PyTango.DeviceProxy("sys/motion/3")
   
   # 检查轴是否使能
   axis_state = motion.command_inout("checkMoveState", 6)
   
   # 检查位置
   pos = motion.command_inout("readPos", 6)
   
   # 检查限位
   el_state = motion.command_inout("readEL", 6)
   ```

3. **调整超时参数**（如果需要）
   
   编辑 `motion_controller_device.h`：
   ```cpp
   static constexpr double POSITION_STABLE_THRESHOLD = 0.1;  // 增大阈值
   static constexpr int POSITION_STABLE_TIMEOUT_MS = 5000;   // 延长超时时间
   ```

4. **查看完整日志**
   ```bash
   tail -f logs/motioncontroller-3.log
   tail -f logs/largestroke.log
   ```
